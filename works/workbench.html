WORK 02 · WEB 看板

招聘作战台

四件套解决「单个环节的效率」，作战台解决「每天的视野」——本地 Web 看板四页，每天开工先打开它，30 秒知道今天该干什么。

角色产品定义 + 前后端
形态本地 Node + 单文件网页，双击即启动
a · 处境 b · 四页看板 c · 三个决定 d · 留下了什么

a处境：信息有了，视野没有

四件套跑顺之后，新问题浮出来：每天的对账数据、业务方的决策信号、候选人的保温状态，分散在三份机器可读的文件里——它们各自正确，但拼不成「今天的行动」。

我需要一个东西：打开就知道今天该碰谁、哪个岗位卡住了、谁的面评还欠着。

b四页看板

架构刻意做薄：看台只读三份契约文件（每日对账 / 决策信号 / 保温状态），写回操作独立实现，互不侵入——数据永远只有一份真相，看台坏了也不影响任何流程。

截图为脱敏演示数据（人名化名、项目转品类描述），界面与真实使用完全一致，面试可现场双击启动演示。

c细节里的三个决定

  • 「30 秒扫读闭环」写进验收：任何一页，30 秒内要能回答「我现在该干什么」；异常必须长得异常——质量、颜色、位置三载体
  • 视觉走「晨间纸质作战简报」：暖纸底、墨色主色、宋体标题——看板不必长得像后台；六工作室各绑专属色相只做归堆标记
  • 写回用乐观更新：页面先变、后台落盘、保滚动局部重绘——浏览不被写操作打断，禁止整页重建回顶

d留下了什么

  • 一个可复制到任何团队的模式：契约文件（数据）+ 看板（视野）+ skill（动作），三层解耦
  • 每日对账从「翻文件」变成「扫一眼」；停滞岗位、欠面评、待保温有了自动预警和写回闭环
